`std::ranges` is a major feature introduced in C++20 that provides a modern, composable approach to working with sequences of data. 

It's built on top of the concepts library and offers both range algorithms and range views.

# Ranges algorithm

Toolbox to replace std::algorithm

- More readable
- Less iterator use

[Standard library header <algorithm> - cppreference.com](https://en.cppreference.com/w/cpp/header/algorithm.html)

```cpp
    if (std::find(ints.begin(), ints.end(), 5) != std::end(ints)) {
        std::cout << "Found 5" << std::endl;   
    }
    
    if (std::ranges::find(ints, 5) != std::end(ints)) {
        std::cout << "Found 5" << std::endl;
    }
```

# Ranges views

### Theoretical Elements for Beginners

### Ranges Concepts Hierarchy

**Range**: Any object you can iterate over

```cpp

cpp
concept range = requires(R& r) {
    ranges::begin(r);// Has a beginning
    ranges::end(r);// Has an end
};

```

**Input Range**: Can read elements once (like reading a file)
**Forward Range**: Can read elements multiple times
**Bidirectional Range**: Can go backwards too
**Random Access Range**: Can jump to any position instantly (like arrays)

### Views vs Containers

**Container** (like `std::vector`):

- Owns its data
- Stores elements in memory
- Modifying operations change the container

**View**:

- Doesn't own data, just "looks at" other ranges
- Lightweight wrapper around existing data
- Non-owning, non-mutating

```cpp
std::vector<int> data = {1, 2, 3, 4, 5};// Container - owns data

auto odds = data | std::views::filter([](int x) { return x % 2 == 1; });
// View - doesn't own data, just filters when accessed

```

### Detailed Views Overview

### Core View Types

- **Transform View** - Applies function to each element:
    
    ```cpp
    auto squared = numbers | std::views::transform([](int x) { return x * x; });
    ```
    
- **Filter View** - Includes only elements matching predicate:
    
    ```cpp
    auto evens = numbers | std::views::filter([](int x) { return x % 2 == 0; });
    ```
    
- **Take View** - First N elements:
    
    ```cpp
    auto first_three = numbers | std::views::take(3);
    ```
    
- **Drop View** - Skip first N elements:
    
    ```cpp
    auto skip_two = numbers | std::views::drop(2);
    ```
    
- **Reverse View** - Elements in reverse order:
    
    ```cpp
    auto backwards = numbers | std::views::reverse;
    
    ```
    

### Advanced Views

- **Join View** - Flattens nested ranges:
    
    ```cpp
    std::vector<std::vector<int>> nested = {{1,2}, {3,4}, {5,6}};
    auto flattened = nested | std::views::join;// 1,2,3,4,5,6
    ```
    
- **Split View** - Splits range on delimiter:
    
    ```cpp
    std::string text = "hello,world,test";
    auto words = text | std::views::split(',');
    ```
    
- **Zip View** (C++23) - Combines multiple ranges:
    
    ```cpp
    std::vector<int> nums = {1, 2, 3};
    std::vector<char> chars = {'a', 'b', 'c'};
    auto pairs = std::views::zip(nums, chars);// (1,'a'), (2,'b'), (3,'c')
    ```
    

### Composition and Chaining

Views compose naturally with the pipe operator:

```cpp
auto result = data
    | std::views::filter([](int x) { return x > 0; })
    | std::views::transform([](int x) { return x * 2; })
    | std::views::take(5)
    | std::views::reverse;
```

Each `|` creates a new view that wraps the previous one. The entire chain remains lazy until iteration begins.

### Materialization

To convert a view back to a container:

```cpp
auto view = numbers | std::views::filter(...) | std::views::transform(...);

// C++23 - direct conversion
std::vector<int> result = std::ranges::to<std::vector>(view);

// C++20 - manual conversion
std::vector<int> result(view.begin(), view.end());
```

The beauty of ranges views is they provide a functional programming style while maintaining C++'s performance characteristics through lazy evaluation and zero-cost abstractions.

### Why `auto` is Essential with Ranges

The compiler-generated type names can be hundreds of characters long and include implementation details you shouldn't need to know.

### Template Type Deduction in Action

### How `auto` Works with Views

```cpp
std::vector<int> data = {1, 2, 3, 4, 5};

// Each step creates a different type:
auto filtered = data | std::views::filter([](int x) { return x > 2; });
// Type: filter_view<ref_view<vector<int>>, lambda>

auto transformed = filtered | std::views::transform([](int x) { return x * 2; });
// Type: transform_view<filter_view<ref_view<vector<int>>, lambda1>, lambda2>

auto taken = transformed | std::views::take(3);
// Type: take_view<transform_view<filter_view<...>, ...>>

```

Each composition creates a new template instantiation wrapping the previous one.

### Lambda Type Deduction

Lambdas have unique, unnamed types that only `auto` can capture:

```cpp
// The lambda has a unique, compiler-generated type
auto predicate = [](int x) { return x % 2 == 0; };

// This won't compile - you can't name the lambda type directly:// ??? predicate = [](int x) { return x % 2 == 0; };// But you could use std::function (with performance cost):
std::function<bool(int)> predicate = [](int x) { return x % 2 == 0; };
```

### `auto` vs Explicit Types

### When `auto` is Preferred (Ranges context):

```cpp
// ✅ Good - clean and maintainable
auto filtered_evens = numbers | std::views::filter([](int x) { return x % 2 == 0; });

// ✅ Good - element type deduction
for (auto&& element : some_complex_view) {
    process(element);
}
```

### When Explicit Types Might Be Better:

```cpp
// When you need to ensure specific type
int sum = 0;// Explicit - we want int accumulation
for (auto value : view) {
    sum += value;// value is deduced, but sum is explicitly int
}

// When interfacing with APIs expecting specific types
std::vector<int> result;
std::ranges::copy(view, std::back_inserter(result));// Explicit container type
```
